# 可复现性能基准

main 分支的 `scripts/benchmark.py` 比较 Git 基线与当前工作区，复制同一份 cmd/bench 到隔离的基线目录后，以相同工具链构建 release native。默认基线为 c37bf22。此入口独立于早前的观测开销测试；完整 132 场景及小块 LZ4 优化结果见文末。

可用 compose.benchmark.yaml 启动专用 Cassandra 5.0.5：2 GiB 堆、256 MiB young 配置、30 秒读写期限和 60 秒通用期限。该项目使用独立名称 mooncql-benchmark，默认密码认证并映射到本机 19042。设置 CQL_PORT=19042、CQL_USERNAME=cassandra、CQL_PASSWORD=cassandra 后运行：

```sh
docker compose -f compose.benchmark.yaml up -d --wait --wait-timeout 360
python scripts/benchmark.py --baseline-ref 50fa621 --trials 3 --server-description "填写服务端系统、JRE、堆大小和网络环境"
```

该脚本创建或覆盖 mooncql_bench.probe 的固定测试分区；应使用本项目专用测试实例。无需 Python 第三方库。`--smoke` 先验证代表性场景，不能代替完整矩阵。每次运行的 manifest、逐条原始记录和最终 result.json 写入 .artifacts/performance-*；latest-performance-dir.txt 指向最近一次目录。失败立即停止并保留错误日志，不将失败算入成功样本。

完整矩阵为 132 个场景，每场景默认三轮，基线与当前共 792 次进程测量：64／400000 字节载荷、ABCD 重复／固定种子 xorshift32 随机数据、普通帧／LZ4，以及真实读写和分页并发 1／32／128。分页页大小为 1／4／8，一次查询完整读取并核对 9 行。随机数据不保证绝对不可压缩，协议仍会在压缩无收益时发送原始载荷。

纯 codec 场景包含 QUERY 编码、envelope、分帧、CRC、可选 LZ4 及重组校验；纯 lz4 场景单独计量压缩与解压，块划分在计时外完成。纯 CPU 场景并发固定为 1。数据库 read 读取一行，write 更新同一行相同内容，page 读取完整 9 行；每个请求核对字段、完整 blob 或返回类型，计时后再次读取验证最终值。每轮先初始化 9 行并预热 8 次，准备请求不计入测量阶段。

记录吞吐、P50／P95／P99 纳秒延迟、进程 CPU 时间与占比、峰值内存；分页同时记录每个成功 next 的延迟。分位数采用 nearest rank，不将三轮样本混成一条分布；汇总为各轮分位数的中位数。CPU 和耗时排除初始化及预热，包含客户端正确性校验和调度；峰值为整个进程生命周期的最大工作集／RSS，含初始化，不是纯运行阶段分配量，也不包含服务端内存。Windows CPU 时间可能受系统记账粒度影响，短测量可能显示高于 100%；不据此推断多核加速。

分页的操作吞吐和主 P50／P95／P99 以完整读取九行的一次查询计量；page_count 和 page_p50_ns／page_p95_ns／page_p99_ns 另统计所有返回 Some(page) 的 next，含服务端返回的空末页。不能将整次查询延迟解释为单页延迟，也不预设每次查询只有 ceil(9/page_size) 个返回页。

固定种子 2026101821 打乱场景／轮次，并为每一对基线与当前随机运行次序。报告记录工具链、平台、服务端说明、源提交、工作区是否修改、编译输入摘要、移除源码路径后的生成 C 摘要及脚本摘要。保留完整原始数据，不能只选择有利场景。代码优化必须超出同代码校准中的波动，并通过相同负载和正确性检查；无可测收益的修改不合入。

初始 [A/A 校准原始数据](benchmarks/calibration-aa-2026-10-18.json) 对应尚未进行库优化的两份构建。移除源码路径后生成 C 相同，但部分小消息 LZ4 和数据库样本仍有明显差异，原因尚未单独定位。这些差异不能作为优化收益；完整测试应扩大样本，按场景报告，不宣称对所有环境成立。

首轮完整矩阵使用 512 MiB 堆和默认 5 秒读取期限，在并发 128、400000 字节随机载荷、页大小 8 时停止。重现得到服务端 ReadTimeout（0x1200），服务端日志记录约 5 秒读超时及多次 Full GC；该轮没有通过完整验收。基准配置随后调整为上述专用实例参数，两版本都在同一新环境重新测量，不能把环境调整算作库优化收益。

## 完整矩阵与小块 LZ4 优化（2026-10-19）

基线为 50fa621，当前编译输入仅有 framing/lz4.mbt 的候选优化差异；两版本使用相同入口及同一个专用实例。完整 132 场景、每场景三轮、共 792 条记录全部通过正确性检查；另核对了记录组合唯一性、汇总中位数、页数，以及当前和基线的编译输入／生成 C 摘要。测量期间编译输入保持不变。

客户端为 Windows native release／MSVC，服务端为 WSL Ubuntu 上的 Cassandra 5.0.5、Eclipse Temurin 17.0.20.1、2 GiB 堆、256 MiB young 配置，密码认证、loopback TCP；其他三个测试节点停止。未固定 CPU 亲和性。原始报告保留平台、工具链、源码摘要和所有样本。

优化按短块大小分配二次幂哈希表，避免每次初始化 65536 个槽；大块仍以 65536 为上限，匹配偏移和内容校验保持。下面是纯计算场景各三轮耗时的中位数；负值表示耗时下降。

| 模式 | 字节 | 数据 | LZ4 | 基线 ms | 优化后 ms | 耗时变化 |
| --- | ---: | --- | --- | ---: | ---: | ---: |
| lz4 | 64 | repeat | 开 | 2786.573 | 1045.134 | -62.49% |
| codec | 64 | repeat | 关 | 334.917 | 346.887 | +3.57% |
| codec | 64 | repeat | 开 | 733.526 | 476.863 | -34.99% |
| lz4 | 64 | random | 开 | 2611.139 | 886.714 | -66.04% |
| codec | 64 | random | 关 | 335.264 | 332.978 | -0.68% |
| codec | 64 | random | 开 | 649.312 | 427.084 | -34.23% |
| lz4 | 400000 | repeat | 开 | 354.140 | 352.643 | -0.42% |
| codec | 400000 | repeat | 关 | 598.832 | 609.521 | +1.79% |
| codec | 400000 | repeat | 开 | 475.954 | 483.530 | +1.59% |
| lz4 | 400000 | random | 开 | 1075.210 | 1094.399 | +1.78% |
| codec | 400000 | random | 关 | 643.067 | 649.706 | +1.03% |
| codec | 400000 | random | 开 | 1391.322 | 1422.789 | +2.26% |

64 字节纯 LZ4 的重复／随机数据分别下降 62.49%／66.04%，对应两组三轮样本互不重叠；64 字节含 LZ4 的 codec 场景下降 34.99%／34.23%。这些结果支持合入小块哈希表优化。大消息纯计算变化约为 -0.42% 至 +2.26%，不宣称大块提速。未启用 LZ4 的对照也有波动。

120 个数据库场景的耗时变化中位数为 -0.55%，各场景范围为 -36.96% 至 +57.21%；该范围提示环境和服务端波动，不能作为数据库整体提速结论。全部场景的吞吐、P50／P95／P99、CPU、峰值内存与分页分位数见[完整原始报告](benchmarks/lz4-full-2026-10-19.json)，没有省略不利场景。

本次仅合入有明确测量收益的小块压缩改动；没有据此改写复制或发送路径。独立 LZ4 双向验证、随机分帧、149 项本地回归和真实数据库集成均已通过。
