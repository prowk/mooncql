# 每节点连接池

[文档目录](README.md) · [连接数评估](pooling-evaluation.md) · [总额度](session-limits.md) · [连接健康](connection-health.md)

本页适用于**尚未发布的开发分支**。`SessionBuilder::new(connections_per_node=...)` 为每个节点设置固定数量的数据连接，默认 **1**，范围 **1–8**。一个 Session 内所有节点使用同一配置，创建后保持固定；控制连接作为独立连接管理。

## 配置与请求路由

Session 继续先按 DC、token 副本和已尝试节点排序，在节点内轮转选取有额度的健康连接。只要该节点还有一条可用连接，节点状态就保持 `Ready`。每条连接仍遵守其 `ConnectionBuilder` 限制，所有数据连接与控制连接合计遵守 `SessionLimits`；增加池大小不会扩大总请求或字节预算。

通过 `Session.prepare` 创建的逻辑语句在选定的物理连接上准备和执行，预处理 ID、参数／结果元数据、准备互斥和缓存均按连接隔离。普通与预处理分页可在不同页选择不同连接，游标仍校验查询语义。一个 BATCH 选定一条物理协调连接后，在该连接准备全部语句并发送整批请求；失败的未知结果 BATCH 仍直接交给调用方。

## 健康、恢复和关闭

每条连接具有独立的 stream 分配、收发任务、心跳、废弃请求和准备缓存。取消后的迟到响应只在原连接排空；单条连接断线只关闭该连接，其他健康连接继续完成请求。发生替换后只重新准备替换连接所需的语句。

同一个已知节点的数据连接和控制连接共享串行握手门限，最多一个恢复握手在途；不同节点可并行连接。每条数据连接独立退避，避免故障时同时重建整池。排空停止新握手、暂停所有心跳，并在操作完成或期限到达后关闭所有连接、等待后台任务。拓扑移除节点时关闭整个节点池并等待对应任务收尾。

`Session.pools()` 返回新建的状态快照：每节点的配置数量、健康数量、实际建连数量，以及每槽的状态、代次、尝试次数、pending、abandoned、stream 空间、额度和缓存大小。修改返回的数组不会改变内部池。`available_streams` 是健康连接上尚未占用的协议 stream ID 数量，最大 32768；实际可发送请求数还受连接和 Session 额度限制。

`NodeStatus.generation` 统计该节点累计接受的物理连接代次。池大小大于 1 时，初始建立多条连接就会增加它；每槽的代次可从池快照读取。初次建立额外连接不计为重连。`Session.resources()` 汇总全部连接及真实后台任务；默认单连接的既有任务数量保持原定义。

## 可运行验证

[只读额度示例](../cmd/limits/main.mbt)支持 `CQL_POOL_SIZE`，等待每个节点的全部连接就绪后，执行十二次系统表读取并断言总额度上限与排空后资源归零：

```powershell
$env:CQL_POOL_SIZE = '3'
moon run cmd/limits
```

连接环境变量与 [Session 总额度](session-limits.md) 相同。CI 在认证与压缩四组合中分别运行默认单连接和三连接，并在三节点环境运行每节点双连接。确定性测试另外注入单连接故障、保留迟到响应、阻塞握手及准备，在同时存在健康兄弟连接时检查故障与元数据隔离。

连接数调整依据[短时测量](pooling-evaluation.md)。默认保持 1；有明确分页负载且单连接通道受限时，可比较 2 与 4，并同时检查尾延迟、CPU、内存和连接任务成本。
